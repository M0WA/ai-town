# Settings / Pause Menu

- **Auto-save**: The simulation auto-saves silently every **120 real seconds (2 minutes) of active gameplay** (the timer pauses when the game is paused or a blocking modal is active). On successful auto-save, display a transient Normal-queue toast: "Game auto-saved" (2 s display, auto-dismiss). On auto-save failure (disk full, permissions error, or I/O error): display a CRITICAL toast: "Auto-save failed — [reason]. Press Ctrl+S to save manually." The Unsaved Changes dot remains visible after a failed auto-save — see `hud-layout.md — Unsaved changes indicator`. **Manual save failure (Ctrl+S)**: must show a blocking error modal (not a silent failure): title "Save Failed", body "[reason]", buttons: "Retry" / "Cancel". This modal follows the standard ModalDialog spec but is dismissable (not forced).
- **Unsaved changes tracking**: `UIManager` maintains a `bool m_hasUnsavedChanges` dirty flag. It is set to `true` whenever any destructive city action is performed (zone placement, road placement, demolition, tax rate change) or when the city simulation fires an economy event (loan, density upgrade). It is cleared to `false` on every successful manual save and on every successful auto-save. The Quit-to-Desktop and Quit-to-Main-Menu paths check `m_hasUnsavedChanges` to determine whether to show the unsaved-changes modal. The Unsaved Changes dot on the HUD reflects this flag directly (`setElementVisible(unsavedDotHandle, m_hasUnsavedChanges)`). **On new game start**: `m_hasUnsavedChanges` is initialized to `false`; it is set to `true` as soon as the first action is performed. This ensures a freshly-started city with no actions cannot trigger an unsaved-changes modal on Quit.
- **Panel ownership**: The pause menu list (Resume, Settings, Save, Quit to Main Menu, Quit to Desktop) is rendered by a dedicated **`PauseMenuPanel`** class. Clicking "Settings" in `PauseMenuPanel` shows `SettingsPanel` as a subordinate view. `SettingsPanel` can also be reached from the main menu. `UIManager::transitionToPaused()` shows `PauseMenuPanel` — there is no ambiguity between `PauseMenuPanel` and `SettingsPanel`; they are separate classes with a clear parent/child relationship.
- **Pause menu** (Escape key): Resume, Settings, Save, **Quit to Main Menu**, Quit to Desktop
  - **Quit to Desktop**: Checks `m_hasUnsavedChanges`. If `true`, shows a blocking modal: title "Unsaved Progress", body "You have unsaved changes.", buttons: "Save and Quit" (saves to current slot then exits) / "Quit Without Saving" (exits immediately) / "Cancel" (returns to pause menu). If `m_hasUnsavedChanges == false`, exits immediately.
  - **Quit to Main Menu**: Same `m_hasUnsavedChanges` check as Quit to Desktop, but transitions to the Main Menu instead of exiting the process.
  - **Save**: Opens a slot selection dialog (3 manual slots + auto-save slot displayed as read-only reference). Saving to an occupied manual slot shows "Overwrite [slot name]? Yes / Cancel." The auto-save slot is overwritten silently on each auto-save trigger; it is not selectable as a manual save target. There is no multiple-slot management beyond this in V1.
- **Settings panel tabs**:
  - Graphics: Resolution, Vsync, MSAA level; **Accessibility** subsection: **Colorblind Mode toggle** — this is the canonical location for the toggle. It switches minimap zone palette, demand bars, zone cursors, and service coverage overlay to colorblind-safe pattern-supplemented encodings. The toggle MUST NOT appear in any other Settings tab. See [Resolution & UI Scaling](resolution-ui-scaling.md) for the full encoding specification.
  - Controls: Edge scroll on/off, mouse sensitivity, key rebindings
  - Audio: Master volume, Music volume, SFX volume — each a float slider in range **0.0–1.0**. Default values: master = 1.0, music = 0.8, SFX = 0.8. Changes apply immediately (see "Audio and Gameplay tabs" note below). Volume settings are persisted in the settings/config file (separate from save game files) and restored on the next session load. `IAudioSystem` interface: `setMasterVolume(float)`, `setMusicVolume(float)`, `setSFXVolume(float)` — all accept a float in [0.0, 1.0]. Volume slider callbacks are fully wired in Phase 8: each slider's onChange handler calls the corresponding `IAudioSystem` method (`setMasterVolume(float)`, `setMusicVolume(float)`, `setSFXVolume(float)`), guarded with `if (m_audio)`, and the wiring is verified by `SettingsPanelTest` in Phase 8.
  - Gameplay: Difficulty tier (read-only during play — set at New Game creation only; see `main-menu-new-game-flow.md`), disaster toggle (**grayed out in V1, labeled "Post-launch"** — disasters are post-V1 scope; the control must be rendered as disabled via `IUIBackend::setElementEnabled(..., false)` with a "Post-launch" label suffix so the UI slot is reserved without implying functional availability; no disaster logic is implemented in V1)
- **Settings panel keyboard navigation**: Settings is a desktop-first application; all functionality must be accessible via keyboard without a mouse.
  - **Default focused tab on open**: the previously active tab, or Graphics on first open.
  - **Tab strip navigation**: Left/Right arrow keys cycle between tab headers. `Ctrl+Tab` / `Ctrl+Shift+Tab` also cycle forward/backward (standard desktop tab-control convention).
  - **Within a tab**: `Tab` navigates between controls in document order (top to bottom, left to right). Apply, Cancel, Restore Defaults are Tab-last in every tab. `Shift+Tab` navigates in reverse order.
  - **Enter**: activates the focused control (button, toggle) or begins editing a focused slider.
  - **Escape from any tab**: equivalent to clicking Cancel — closes Settings, reverts all pending changes, returns to Pause Menu.
  - The Settings panel must never trap keyboard focus in a way that prevents the above navigation. If a keybinding capture is in progress (Controls tab), `Escape` cancels the capture (same as clicking Cancel on the capture widget) before falling through to the tab's Escape handler.
- **Settings panel controls**: All tabs share three bottom buttons: **Apply**, **Cancel**, **Restore Defaults**.
  - **Audio and Gameplay tabs**: Changes apply immediately (low reversal risk). Apply/Cancel still present for consistency.
  - **Graphics tab** (Resolution, Vsync, MSAA): Changes are staged. Clicking Apply triggers a "Confirm display change?" modal with a **10-second wall-clock countdown** that auto-reverts if not confirmed. The countdown uses real elapsed seconds (`IClock::nowSeconds()`) — not simulation ticks — so it always expires in 10 real seconds regardless of simulation speed or pause state. If the player does not click Confirm within 10 seconds, settings revert to pre-Apply values. The countdown is displayed numerically in the modal body (e.g., "Reverting in 8s...") and decrements each real second.
  - **Controls/Keybindings tab**: Existing conflict detection remains. Cancel reverts all pending keybinding changes in the current session. Apply writes to `keybindings.json` only after a conflict-free state is confirmed. **Escape behavior on this tab**: Pressing Escape is equivalent to clicking Cancel — pending keybinding changes are reverted and the Settings panel closes (returning to the Pause Menu). This is the same behavior as Escape on all other tabs. **Note**: since Escape is the close/cancel key for the Settings panel, it cannot be rebound to a game action while the Settings panel is open (handled by the input arbitration layer).
  - **Restore Defaults**: Shows "Reset all [Tab name] settings to defaults? Yes / Cancel."
