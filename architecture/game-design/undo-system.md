# Undo System

- **V1 scope**: Single-level undo (`Ctrl+Z`) covering the last **destructive player action** (zone placement, road placement, demolition). Undo is not available for economy events (loans, tax changes) or simulation-driven events.
- **Undo semantics**: The undone action is fully reversed: placed tiles are removed, demolished tiles are restored, spent funds are refunded at the original cost. If the refund would exceed the starting capital cap, the treasury is clamped (no negative refunds).
- **Undo expiry at second budget tick**: The pending undo action is cleared when the **second** budget tick fires after the undoable action was taken (not the first). **Rationale**: A single budget tick's revenue on a single tile is negligible — the anti-exploit concern applies to multi-tick revenue farming (player places zone, waits multiple ticks collecting revenue, then undoes). Expiring at the second tick provides a minimum real-time window of ~20 seconds at 3× speed (2 × 10 s), which is sufficient for normal gameplay without enabling exploit. At 1× speed the window is ~60 real seconds; at 10× it is ~6 real seconds. **Why not first tick**: At 3× speed (the default starting speed), the first tick fires in ~10 real seconds — barely enough time for a player to review a placement, read a notification toast, or consult the Inspector panel. Expiring at the first tick makes undo unreliable at the game's default speed. The second-tick rule is the minimum extension that preserves exploit protection while keeping undo usable. After two budget ticks fire, the economic state has diverged sufficiently to make full reversal impractical. The HUD undo button must be grayed out after the second budget tick clears the pending undo. **Undo expiry countdown**: When an undoable action is pending, the HUD undo button displays a countdown showing the time remaining until the second budget tick (when undo will expire). The countdown reads "↩ Undo (expires in Xs)" where X is the real-time seconds until the second tick, updating every second. At simulation speeds ≥ 3×, the countdown updates every real second (not every simulation second) — the player must be warned in real time. When less than 5 real seconds remain, the countdown text turns amber as a last-chance visual cue. **High-speed exception**: At simulation speeds ≥ 10× (second tick fires in ~6 real seconds), the entire undo window is a last-chance window — the countdown is displayed in amber from the moment the undoable action is taken. Implementation: on each undo countdown render tick, compute `remainingSeconds = secondBudgetTickTimeReal - nowSeconds()`; set amber if `remainingSeconds < 5.0 || totalWindowSeconds <= 6.0`. If the player has no undoable action (button grayed out), no countdown is displayed. This prevents the common failure mode where a player places a zone, forgets to undo before the window expires, and loses the undo window silently.
- **Paused simulation behavior**: Undo expiry is fundamentally **budget-tick-driven** — the pending undo clears when the second budget tick fires after the undoable action. Budget ticks do NOT fire while the simulation is paused, so **the undo window cannot expire during pause**. The wall-clock expiry time (`secondBudgetTickTimeReal`) used by the HUD countdown is a derived display value only; it must be **recomputed on unpause** (and on speed change while paused) so the countdown remains accurate after unpausing: `m_undoExpiryWallTime = IClock::nowSeconds() + m_remainingUndoSimSeconds / effectiveSpeedMultiplier`. At pause time, record `m_remainingUndoSimSeconds = m_undoBudgetTickDeadline * SECONDS_PER_BUDGET_TICK - m_simTimeAccumulator` (the remaining simulation seconds until the second tick fires). **HUD countdown while paused**: the countdown label is static (last pre-pause value; does not decrement during pause) — real-time progress toward the deadline has stopped. **`UndoSystem_PausedSimulation_UndoWindowDoesNotExpireDuringPause` test contract**: advance `ManualClock` past the original predicted `secondBudgetTickTimeReal` without firing any budget ticks (i.e., while paused); assert that the pending undo is still valid. This test verifies the expiry is tick-based, not clock-based.
- **Blocked undo**: Undo is unavailable while a blocking modal is active. The Undo button/hotkey must be grayed out and non-functional during modal dialogs.
- **HUD indicator**: The toolbar shows a grayed-out undo icon when no undoable action is available, and a highlighted icon when one is available — so players know undo exists and is ready.
- This design decision is **final for V1**. A full undo stack is post-V1 scope.
