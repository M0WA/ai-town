# Save System

- **Auto-save triggers**: Every **120 real seconds** OR every **5 budget ticks**, whichever comes first — and when the player opens the Pause Menu (before displaying it). The time-based trigger ensures players at 1× speed do not lose more than 2 minutes of progress regardless of tick rate. Additionally, auto-save triggers **immediately when the forced loan dialog becomes active** (before the modal is shown), ensuring pre-crisis city state is always saved and "Load Last Save" in the game-over modal reflects a meaningful restore point.
- **Save slots**: 1 auto-save slot (overwritten silently) + 3 manual save slots (player-named or auto-named with timestamp)
- **Save format**: JSON for V1 (human-readable, debuggable); binary serialization is post-V1 optimization
- **Save file location**: `~/.config/aitown/saves/` on Linux; `%APPDATA%\aitown\saves\` on Windows (consistent with `keybindings.json` path convention)
- **Manual save**: The Pause Menu > Save opens a slot selection dialog showing 3 slots with their timestamps. Saving to an occupied slot shows a brief confirmation "Overwrite [slot name]? Yes / Cancel."
- **Quit to Desktop safety**: Selecting Quit to Desktop checks if unsaved progress exists since the last save. If so, shows a blocking modal: "You have unsaved progress. Save and Quit / Quit Without Saving / Cancel." This modal follows the standard ModalDialog system and blocks scene input.
- **Load Last Save (Game Over)**: Loads the most recent save across all slots (auto-save or manual), sorted by timestamp. If no save exists, the "Load Last Save" button is grayed out with tooltip "No save file found."
- **Save in Scenario mode**: Scenario mode saves include scenario state (win condition progress, starting conditions). Scenario saves are stored in a dedicated `scenarios/` subdirectory.
- **Population milestone serialization**: The save JSON MUST include a `population_milestone_fired` boolean array of exactly 5 elements, one per threshold (1K/10K/50K/100K/500K). Each element is `true` once the corresponding milestone has fired; `false` otherwise. On load, `CitySimulation` restores these flags to prevent already-fired milestones from re-triggering. Default-constructed value (new game) is `[false, false, false, false, false]`. See `SimulationConstants::population_milestone_threshold_1..5` for threshold values. Cross-reference: `implementation/phase-6.md` (Phase 11 promises — milestone flag serialization note).
- **Speed multiplier serialization**: The save JSON MUST include a `speed_multiplier` field storing the integer representation of the `SpeedMultiplier` enum value active at save time. On load, `CitySimulation` restores this field so that the simulation resumes at the saved speed. After loading, `getSpeedMultiplier()` MUST return the value that was serialized. Default-constructed value (new game) is `SpeedMultiplier::x3` (the default starting speed per `architecture/game-design/simulation-time.md` — there is no `NORMAL` enum value). This field is verified by the `SaveSystem_RoundTrip_PreservesFullCityState` test in Phase 11.
- **Building variant counter serialization** (Phase 11 scope): The save JSON MUST include a `building_variant_counters` array of exactly 9 integers, representing `CitySimulation::m_buildingVariantCounters` indexed by `zone * 3 + tier` (where `zone` = 0/1/2 for Res/Com/Ind and `tier` = 0/1/2 for Low/Med/High). On load, `CitySimulation` restores these counters so that round-robin variant selection resumes the existing sequence rather than restarting from 0. Without this, the first tile placed after a load always receives variant `01`, producing visible repetition when the pre-save sequence had already advanced to `02`. Default-constructed value (new game) is `[0, 0, 0, 0, 0, 0, 0, 0, 0]`. This field is verified by the `SaveSystem_RoundTrip_PreservesFullCityState` test in Phase 11. Cross-reference: `architecture/asset-standards/3d-model-standards.md` §91 ("Counter serialisation is Phase 11 scope").
