## Phase 1: Irrlicht Device Shell & Camera

### Goal

Establish the Irrlicht device lifecycle, render loop call order, `CameraController`, `IRenderer` interface, and `IrrlichtUIBackend` compile target — giving all subsequent phases a working, compilation-verified display target to build against, before any GL capability queries or texture infrastructure is added in Phase 2.

### Deliverables

#### Graphics / Render System

- [ ] `RenderSystem` class: owns `IrrlichtDevice*` (RAII, `device->drop()` in destructor); `EDT_OPENGL` on all platforms; log and abort if OpenGL unavailable (ref: `architecture/graphics-architecture/irrlicht-device-lifecycle.md`)
- [ ] `SIrrlichtCreationParameters`: `EDT_OPENGL`, `Bits=32`, `ZBufferBits=24`, `Stencil=true`, `AntiAlias=4`, `Vsync=false`, initial window `1280×720` (ref: `architecture/graphics-architecture/irrlicht-device-lifecycle.md`)
- [ ] **`glewInit()` in `RenderSystem` constructor** (`graphics-dev-irrlicht`): immediately after `createDevice()` returns non-null (guard the `EDT_NULL` short-circuit path), the `RenderSystem` constructor MUST:
  1. Set `glewExperimental = GL_TRUE` then call `glewInit()`.
  2. Handle `GLEW_ERROR_NO_GL_VERSION` as a non-fatal warning (log and continue — do NOT abort, do NOT fall back to `EDT_NULL`).
  3. **Three-tier response based on `glewResult`**:
     - **SUCCESS path** (`glewResult == GLEW_OK` OR `glewResult == GLEW_ERROR_NO_GL_VERSION`): call `glGetIntegerv(GL_MAX_TEXTURE_SIZE, &m_maxTextureSize)`; store result as member `m_maxTextureSize`. (ref: `architecture/graphics-architecture/irrlicht-device-lifecycle.md` step 3)
     - **Fatal failure in DEBUG builds** (any other `glewResult`): abort immediately (hard assert or `std::abort()`).
     - **Fatal failure in RELEASE builds** (any other `glewResult`): re-initialize the device with `EDT_NULL`; set `m_maxTextureSize = 2048` WITHOUT calling `glGetIntegerv` (no GL context is current after `EDT_NULL` re-init); display a user-facing error notification.

  This requires `find_package(GLEW REQUIRED)` and linking `GLEW::GLEW` BEFORE `Irrlicht` in `aitown_render` (see co-landing requirement in Windows DLL CI section below). The Phase 2 GLEW spike answers whether the vendored Irrlicht build strips its bundled GLEW — the `glewInit()` call itself is a **Phase 1 mandatory requirement**, not a Phase 2 deliverable.

- [ ] Render loop call order enforced: `beginScene` → `sceneManager->drawAll()` → `UIManager::draw()` → `endScene()`. **`m_gui->drawAll()` is NOT called by `RenderSystem`** — per `architecture/graphics-architecture/irrlicht-device-lifecycle.md` and `architecture/ui-ux/ui-manager.md`, `UIManager::draw()` issues explicit per-panel draw calls in Z-order via `IUIBackend`; calling `m_gui->drawAll()` would bypass the explicit layering required for the background scrim and modal overlay. The `IRenderer` facade exposes `endFrame()` as its abstract method name — this wraps `driver->endScene()` internally (Irrlicht has no `endFrame()` method; calling `endFrame()` on any Irrlicht object is a compile error). **Per-frame execution sequence rule** (`graphics-dev-irrlicht`): ALL simulation logic updates and audio updates (`CitySimulation::tick()`, `AudioSystem::syncListenerToCamera()`, `AudioSystem::update()`) MUST execute BEFORE `RenderSystem::beginFrame()` (`driver->beginScene()`) — never interleave logic updates inside the begin/end scene block. The canonical 7-step frame sequence is:
  1. Poll events (device->run() + SEvent dispatch)
  2. `// TODO Phase 6: citySimulation.tick(realDeltaSeconds)` — stub comment at main loop call site; do NOT implement until Phase 6; `WallClock::nowSeconds()` delta must be computed here as raw real-world frame delta (NEVER pre-multiplied by speed multiplier — `CitySimulation` owns all speed-scaling internally per `architecture/game-design/simulation-time.md`). **`CitySimulation` must be constructed with default speed `SpeedMultiplier::x3` per `architecture/game-design/simulation-time.md` — NOT `x1` or `Paused`. The Phase 6 implementer must verify the `CitySimulation` constructor or post-construction `setSpeed()` call initializes at `x3` before this stub comment is replaced with live code.**
  3. `CameraController::update(dt)`
  3b. `UIManager::update(realDeltaSeconds)` — per-frame UI state update (undo countdown, grace-period indicator, notification auto-dismiss timers). MUST execute BEFORE `beginFrame()` per `architecture/ui-ux/ui-manager.md`. Phase 1 stub: reserve this call site with a stub comment — a stub `UIManager` or forward-declared stub must allow this call to compile. Phase 3 wires the real `UIManager` without restructuring the main loop.
  4a. `AudioSystem::syncListenerToCamera(cameraState)` — passes the current `CameraState` struct (position, forward, up vectors) to commit `AL_POSITION`, `AL_VELOCITY=0`, and `AL_ORIENTATION` to the OpenAL context BEFORE `AudioSystem::update()` reads the committed listener position. (The variable name `cameraState` is illustrative; the actual call-site variable name is the implementer's choice. The plan requires that a `CameraState`-typed argument is passed.) See `architecture/audio-architecture/spatial-audio.md` for the full three-attribute commit sequence.
  4b. `AudioSystem::update(realDeltaSeconds)` — then performs ALL three main-thread responsibilities: (1) advance occlusion raycast budget and process per-source distance cull checks (depends on listener position committed by step 4a); (2) push time-of-day transitions; (3) QUEUES crossfade command objects to the audio thread via a mutex-protected command queue; `AudioSystem::update()` MUST NOT call `alSourcef(AL_GAIN)` directly on streaming sources from the main thread (per `architecture/audio-architecture/dynamic-soundscape.md`). The OAL-2 comment at the call site MUST include this threading constraint.
  5. `RenderSystem::beginFrame()` — wraps `driver->beginScene()`
  6. `RenderSystem::drawScene()` — wraps `sceneManager->drawAll()` + `uiManager->draw()` (both inside the single `beginScene`/`endScene` pair)
  7. `RenderSystem::endFrame()` — wraps `driver->endScene()`

  **realDeltaSeconds provenance**: `realDeltaSeconds` (or `dt`) is the raw `WallClock::nowSeconds()` delta computed ONCE per frame at the top of the frame loop before step 3. The same raw wall-clock delta is passed to both `CameraController::update(dt)` (step 3) and `AudioSystem::update(realDeltaSeconds)` (step 4b) — no speed multiplier is applied at any intermediate step between these calls. The variable must be computed as `realDeltaSeconds = currentTime - previousTime` at the top of the frame before step 3.

  **OAL-2 ordering rule**: `CameraController::update(dt)` at step 3 MUST execute BEFORE `AudioSystem::syncListenerToCamera(cameraState)` at step 4a — the listener must read the camera position AFTER it has been updated for the current frame. **Step 4a MUST precede step 4b** — `update()` advances the occlusion raycast budget using per-source distance cull checks that reference the current listener position already committed to the OpenAL context by `syncListenerToCamera()`; processing occlusion checks before the listener is updated would use one-frame-stale position data. Additionally, `update()` pushes pending time-of-day transitions and zone-layer source cull/acquire decisions (per `IAudioSystem::update()` docstring in `architecture/audio-architecture/audio-system.md`); these writes must complete before `beginScene()` to avoid interleaving state mutations inside the Irrlicht begin/end scene block. (Note: gain writes to streaming sources are the audio thread's exclusive responsibility — not performed by main-thread `update()`.) The OAL-2 rule comment at the main loop call site must document ALL three main-thread responsibilities of `AudioSystem::update()`: (1) occlusion raycast budget + distance cull checks, (2) time-of-day transition pushing, (3) pending crossfade/zone-layer source update forwarding. **A comment covering only responsibility (1) does NOT satisfy the Phase 1 exit criterion for this comment.** This sequence must be documented as a comment at the main loop call site. (ref: `architecture/graphics-architecture/irrlicht-device-lifecycle.md`, `architecture/audio-architecture/audio-system.md`, `architecture/audio-architecture/spatial-audio.md`, `architecture/ui-ux/ui-manager.md`)

#### Platform Layer

- [ ] `src/platform/input_event.h` — defines the `InputEvent` struct with `Type` enum (`MouseMove`, `MouseButtonDown`, `MouseButtonUp`, `MouseWheel`, `KeyDown`, `KeyUp`, `WindowFocusGained`, `WindowFocusLost`), `x`/`y` (virtual 1920×1080 space, for UI hit-testing), `physX`/`physY` (physical pixels, for drag-delta in `CameraController`), `button`, `wheelDelta`, `keyCode` fields. The platform `IEventReceiver` populates both `x/y` (from `UIScaler::unproject()`) and `physX/physY` (raw `SEvent` coordinates before unproject). This header is required for `CameraController::OnInputEvent()` and `UIManager::onEvent()`. (ref: `architecture/testing/testability-architecture.md`)
- [ ] Platform `IEventReceiver` adapter in `src/platform/` that translates Irrlicht `SEvent` to `InputEvent` — populates `x/y` via `UIScaler::unproject()` and `physX/physY` from raw `SEvent` mouse coordinates; forwards to `UIManager::onEvent()` then to `CameraController::OnInputEvent()` per the 6-priority input arbitration chain. **Short-circuit dispatch rule (MUST be authored in Phase 1)**: call `UIManager::onEvent(event)` first; only if it returns `false` (event not consumed) forward to `CameraController::OnInputEvent(event)`. Exception — camera pass-through events (MMB drag: `MouseButtonDown/Up button=2`, `MouseMove` while MMB held, `MouseWheel`) always reach `CameraController` regardless of `UIManager::onEvent()` return value, per `input-arbitration.md` Priority 1 pass-through rule. **RMB drag distinction**: The adapter tracks `m_rmbDragActive` boolean state: set to `true` on `MouseButtonDown button=1`; cleared on `MouseButtonUp button=1`. `MouseMove` events while `m_rmbDragActive == true` always pass through to `CameraController` regardless of `UIManager::onEvent()` return value. The `MouseButtonDown button=1` event itself is forwarded to `UIManager::onEvent()` first; if `UIManager` returns `true` (scrim consumed the click), `m_rmbDragActive` is NOT set and the event does not reach `CameraController`. If `UIManager` returns `false`, `m_rmbDragActive` is set and the drag sequence begins. This matches the intent of `architecture/ui-ux/input-arbitration.md` — RMB drag (rotate/pan) bypasses the scrim while bare RMB clicks can be consumed by an active modal. Window focus events (`WindowFocusGained`, `WindowFocusLost`) also always reach `CameraController` regardless of `UIManager::onEvent()` return value — `CameraController` is the sole consumer of these events for `m_appHasFocus` state management. This dispatch contract must be authored in Phase 1 even though UIManager is a stub — Phase 3 integration must not require structural rework of the adapter. **Scrim LMB/RMB comment block (MUST be present)**: The dispatch contract MUST also document — as a comment at the call site in the platform adapter — that `UIManager::onEvent()` returning `true` for a left-click (`MouseButtonDown button=0`) or right-click (`MouseButtonDown button=1`) event while a modal is active is CORRECT behavior (the scrim element is consuming those events at Priority 1 per `architecture/ui-ux/input-arbitration.md`). Phase 8 integration MUST NOT reinterpret `UIManager::onEvent()` returning `true` for those events as a bug. (ref: `architecture/ui-ux/input-arbitration.md`, `architecture/testing/testability-architecture.md`)
- [ ] `src/platform/WallClock.cpp` — implements `WallClock::nowSeconds()` using `std::chrono::steady_clock`; the `WallClock.h` stub header was delivered in Phase 0 in `src/interfaces/`; this Phase 1 deliverable is the concrete `std::chrono`-based body only. **IMPORTANT**: The raw delta from `WallClock::nowSeconds()` must NEVER be pre-multiplied by a speed multiplier at the call site or main loop level. `CitySimulation::tick()` owns all speed-scaling internally per `architecture/game-design/simulation-time.md`. Phase 1 stub code must not introduce any speed multiplier at the main loop. (ref: `architecture/testing/testability-architecture.md` IClock section)
- [ ] `UIScaler` implementation in `src/ui/UIScaler.cpp` — implement `UIScaler::unproject()` (letterbox offset formula per `architecture/ui-ux/resolution-ui-scaling.md`, output clamped to `[0, virtualW] × [0, virtualH]`) and `UIScaler::getViewportRect()` (returns active viewport in physical pixels). The Phase 0 `UIScaler.h` stub must be filled in Phase 1 because the platform `IEventReceiver` adapter calls `UIScaler::unproject()` to populate `InputEvent.x/y` — without this, all virtual coordinates are 0. (`graphics-dev-irrlicht` or `gamedesign-ux`)

#### CameraController

- [ ] `CameraController` class in `src/ui/`: pan (Middle-mouse-button drag + Arrow keys), zoom (scroll wheel), rotate (Right-mouse-button drag only — Q/E NOT bound); pitch clamped to `[-70°, -20°]` inclusive bounds (`std::clamp` semantics); **default window mode is `windowed` (not fullscreen) at 1920×1080 virtual resolution**; edge scrolling ON by default in exclusive fullscreen, OFF by default in windowed mode; `m_appHasFocus` flag disables edge-scroll on focus loss (note: `m_appHasFocus = false` overrides edge-scroll at the input processing point but does NOT change the stored `m_edgeScrollEnabled` value — restoring focus resumes edge-scroll if enabled is true); constructor must accept `bool startInFullscreen` parameter setting initial `m_edgeScrollEnabled` state; public API must include `bool isEdgeScrollEnabled() const` returning the current value of `m_edgeScrollEnabled` — this accessor is required by test case 6; **public API must also include `void setEdgeScrollEnabled(bool enabled)` as a setter that updates `m_edgeScrollEnabled`** — this setter is required by the Phase 8 Settings panel wiring; edge-scroll activation band is **20 px** from the virtual viewport edge (x < 20, x > 1900, y < 20, y > 1060 in 1920×1080 virtual space). (ref: `architecture/ui-ux/camera-controls.md`, `architecture/testing/testability-architecture.md`)
- [ ] `CameraController` accepts `InputEvent` struct from `src/platform/input_event.h`; `OnInputEvent(const InputEvent&)` method replaces `OnEvent(SEvent&)` in the `CameraController` public interface; returns `true` (consumed) for all relevant event types. (ref: `architecture/testing/testability-architecture.md`)

  **NOTE (UX-1 — Drag-delta coordinate space)**: Drag-delta calculations for pan (MMB drag) and rotate (RMB drag) MUST use physical pixel delta via `InputEvent.physX`/`InputEvent.physY` — NOT the virtual-space `InputEvent.x`/`InputEvent.y` values. Camera controller unit tests must inject `physX`/`physY` values for drag-delta tests (cases 4 and 5) and document this in test comments. (ref: `architecture/ui-ux/camera-controls.md` Drag-delta coordinate space section, `architecture/testing/testability-architecture.md`)
