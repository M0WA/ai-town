### Risks & Spikes

- **RISK**: Loan pooling with multi-loan scenarios produces complex remainder arithmetic. **Spike**: prototype the multi-loan repayment formula in isolation and validate against the spec's $10,001 example before wiring into `CitySimulation`.
- **RISK**: Demand coupling bootstrapping decay may cause oscillation in early game at 3× speed. **Spike**: run simulation for 10 ticks at 3× with a blank map and trace demand_factor values per zone type. (Bootstrap oscillation design review gate was a Phase 4 exit criterion.)
- **RISK**: `ManualRNG` sequence audit — under-provisioning `floatSeq` causes `std::logic_error` at runtime (not compile time). **Mitigation**: before writing any Phase 6 test that initializes `ManualRNG` with a fixed sequence, manually trace the exact number of `nextFloat()` / `nextInt()` calls the simulation path exercises; document the count as a comment. Use strict mode (`ManualRNG{{0}, {}, true}`) in all unit tests to catch mismatches immediately. See testability-architecture.md for the ManualRNG audit requirement.
- **RISK**: A\* pathfinding timeout in CI — path search over large grids (64×64) may exceed 10 ms per agent at the default max-iterations limit, causing CI test flakiness. **Spike**: run `TrafficAgent_Timeout_LoggedAsExtremeTravel_NotNullPath` with a 64×64 fully connected grid under `valgrind --tool=callgrind`; if A\* dominates, cap iteration count or reduce default test grid size to 32×32.
- **RISK**: `int64_t` treasury precision in property tests — RapidCheck may generate treasury values near `INT64_MAX` that overflow in intermediate arithmetic (e.g., `interest = treasury × rate / ticks_per_year`). **Mitigation**: bound the `rc::gen::inRange` treasury generator to a safe maximum (e.g., $10B = `10'000'000'000LL`) well below `INT64_MAX / (max_interest_rate × ticks_per_year)`. **NOTE on float display**: if any UI or debug code formats treasury balance as `float`, values above ~$16.7M (2^24) lose integer precision; Phase 6 simulation code MUST use `int64_t` throughout (no float cast in simulation paths); float formatting is a Phase 8 HUD concern, not a simulation invariant.
