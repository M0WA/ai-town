     | Stingers (crisis/milestone; game-over post-V1) | −18 LUFS | −1 dBTP |
     | Ambient beds (ambient_day/night/dawn/dusk) | −20 LUFS | −1 dBTP |
     | CRITICAL service alerts (fire/police), vehicle horn | −18 LUFS | −1 dBTP |
     | Budget deficit warning | −20 LUFS | −1 dBTP |
     | Important gameplay notifications (zone_upgrade, service_degrade, power_out, water_out) | −22 LUFS | −1 dBTP |
     | General feedback SFX (build, demolish, road, loan, earthworks) | −24 LUFS | −1 dBTP |
     | Very subtle ambient detail (intersection_tick) | −28 LUFS | −2 dBTP |
     | Vehicle engine (idle/move) | −22 LUFS | −2 dBTP |
     | Zone loops | −26 LUFS | −2 dBTP |
     | UI sounds (click, toast, menu) | −22 to −24 LUFS | −1 dBTP |

  3. **Channel count rules**: Music stems and ambient beds: **stereo (2 channels)**; Zone loops: **mono (1 channel)** positional — mono is mandatory for `alSource3f(AL_POSITION)` 3D spatialization to work (OpenAL ignores 3D position on stereo sources); Stingers (`stinger_crisis`, `stinger_milestone`): **mono (1 channel)** — stingers are non-positional (`AL_SOURCE_RELATIVE = AL_TRUE`) but must be mono because multi-channel WAV sources with `AL_SOURCE_RELATIVE` produce undefined panning on some OpenAL implementations; **Positional SFX** (all `sfx_*` assets that are spatially placed — `sfx_fire_alert`, `sfx_police_alert`, `sfx_vehicle_horn`, `sfx_intersection_tick`, zone loops): **mono (1 channel)** — OpenAL ignores `AL_POSITION` on stereo sources entirely; stereo positional SFX is a silent correctness failure, not a runtime error; **Vehicle engine SFX** (`sfx_vehicle_engine_idle`, `sfx_vehicle_engine_move`): **mono (1 channel) OGG Vorbis** — WAV format is prohibited for vehicle engine loops (a 1–2 s WAV loop is audibly mechanical; OGG minimum duration 6 s required per item 5); UI sounds: `AL_SOURCE_RELATIVE = AL_TRUE`.
  4. **Loop authoring rules** — three distinct methods depending on asset type:
     - **Bar-aligned seamless loop** (music stems): no silence or crossfade at loop boundary; loop point must align to a bar boundary at the authored BPM (e.g., at 90 BPM with 4/4 time, a loop of N bars = N × (4 beats × 60/90 s) = N × 2.667 s); coded in the JSON sidecar; `AudioSystem` implements bar-boundary crossfade in software.
     - **DAW crossfade loop** (ambient beds): the ambient bed must satisfy BOTH (1) 200 ms pre-baked crossfade tail at end of file authored in the DAW (not handled at runtime); the `.ogg` file sounds seamless at the embedded loop boundary; no silence floor permitted; AND (2) seamless sample-0 boundary — because the streaming runtime seeks to sample 0 (`ov_pcm_seek(vf, 0)`) BEFORE the crossfade tail, bypassing it entirely. Authors must verify the sample-0 boundary is click-free and transient-free using DAW loopback-audition, in addition to verifying the crossfade tail.
     - **Silence-boundary loop** (zone loops): −60 dBFS or lower at both head and tail of the file; the final 100 ms (tail) and the first 100 ms (head) must fade to and from silence (floor: −60 dBFS or lower). Both boundaries must individually reach −60 dBFS or below. The resulting ~200 ms silence window at every loop boundary must coincide with a natural rhythmic gap in the content. Mandatory DAW verification: authors must loop the file in the DAW player, listen through the boundary, and confirm the 200 ms silence coincides with a natural gap. Loop audibly fades in and out naturally; no DAW crossfade or bar alignment needed — the silence boundary provides a natural restart point. **Zone loop hard duration cap: 18 s** — zone loops must not exceed 18 s authored duration. The pre-load tier boundary is 20 s; the 18 s cap provides a 2 s safety margin. Zone loops exceeding 18 s fall into the streaming tier and are incompatible with the pre-loaded AL buffer loading strategy used by the zone audio system (ref: `architecture/audio-architecture/v1-audio-asset-manifest.md`).
  5. **Vehicle engine minimum duration**: `sfx_vehicle_engine_idle` and `sfx_vehicle_engine_move` must be **minimum 6 s** (not 4 s or 5 s); rationale: at the lowest pitch-shift ratio (0.75), a 4 s loop produces a ~3 s perceived loop — audibly mechanical; at 6 s minimum, the perceived loop is ~4.5 s, below the perceptibility threshold. **Vehicle horn minimum authored duration**: `sfx_vehicle_horn` must be a minimum of **0.4 s** authored duration — sub-0.4 s sounds are perceptually indistinguishable from UI click feedback and do not read as a horn (ref: `architecture/audio-architecture/v1-audio-asset-manifest.md`). Rate-limiting rules (2 s per-vehicle cooldown, ≤3 simultaneous horn sources, 100 m cull distance) are enforced by `AudioSystem` at runtime — these are not authoring constraints.
  6. **Flat asset path convention**: all V1 audio assets are placed directly in `assets/audio/` with no subdirectories (e.g., `assets/audio/ambient_day.ogg`, `assets/audio/sfx_build_place.wav`). JSON sidecars are also in the same flat directory (e.g., `assets/audio/music_calm_01.json`).
  7. **OGG encoding quality settings** (sourced from `architecture/audio-architecture/audio-asset-formats.md`): all OGG files must be encoded at 44100 Hz with consistent quality settings to avoid inter-file loudness variation:

     | Asset category | libvorbis quality | Approx. bitrate |
     |---|---|---|
     | Music stems | `-q 8` | ~256 kbps VBR stereo |
     | Ambient beds | `-q 7` | ~224 kbps VBR stereo |
     | Zone loops | `-q 6` | ~192 kbps VBR mono |
     | Vehicle engine loops (`sfx_vehicle_engine_idle`, `sfx_vehicle_engine_move`) | `-q 6` | ~192 kbps VBR mono (pre-loaded, positional) |

     Inconsistent encoder quality settings cause inter-file loudness variation and may produce mismatch between authored loudness targets and decoded output. Never use `-q 10` (unnecessarily large files) or `-q 4` or lower (audible compression artifacts).

  8. **Harmonic compatibility and crossfade audibility requirement** (ref: `architecture/audio-architecture/dynamic-soundscape.md`): All 6 gameplay stems (`music_calm_01`, `music_calm_02`, `music_growth_01`, `music_growth_02`, `music_crisis_01`, `music_crisis_02`) MUST share the same root key and mode. During bar-boundary crossfades, two stems are simultaneously audible for 3 s — different keys or modes produce audible harmonic clashes at the crossfade transition. **Mandatory delivery gate**: the audio artist must submit a crossfade audibility test (manually mix `music_calm_01` with `music_growth_01` for 3 seconds at equal gain, verify no harmonic clash) as part of the Phase 4 asset delivery package. Main menu variants (`music_main_menu_01`, `music_main_menu_02`) must share the same root key and mode as gameplay stems — `architecture/audio-architecture/dynamic-soundscape.md` states this harmonic compatibility constraint applies equally to main menu music variants (even though main menu and gameplay are mutually exclusive states that never crossfade directly stem-to-stem, harmonic compatibility is architecturally mandated; main menu variants must also be internally compatible with each other).

  **2D Texture pipeline constraints** (ref: `architecture/asset-standards/2d-texture-standards.md`):
  - Upload categories and formats: (a) diffuse sRGB opaque → DXT1/BC1 raw-GL sRGB path (`glCompressedTexImage2D` with `GL_COMPRESSED_SRGB_S3TC_DXT1_EXT`); (b) diffuse sRGB with alpha → DXT5/BC3 raw-GL sRGB path (`glCompressedTexImage2D` with `GL_COMPRESSED_SRGB_ALPHA_S3TC_DXT5_EXT`); (c) normal maps → DXT5nm (BC3) linear pool (`IVideoDriver::getTexture()` — Irrlicht loads the DXT5nm DDS file and manages the GL object; `GL_COMPRESSED_RGBA_S3TC_DXT5_EXT` is the internal format Irrlicht uses for DXT5 DDS files automatically; do NOT call `glCompressedTexImage2D` directly for normal maps — this bypasses `TextureCache`'s linear pool tracking and causes texture leaks on eviction, **DDS export pipeline (must be applied in order)**: Step 1 — Y-convention correction: if sourcing from a DirectX-convention baker (e.g. Substance Painter with DirectX normals enabled), **invert the green channel** before compression; skip if baker is already set to OpenGL convention. Normal maps must use OpenGL convention (Y-up: green channel points toward +Y in tangent space). Step 2 — DXT5nm swizzle: copy **X (red channel) into A (alpha channel)**, keep Y in green channel, discard Z (blue) — the shader samples `.a` for X and `.g` for Y; export the swizzled result as an intermediate PNG file (`input_swizzled.png`) before the next step. Validate with a sphere test: a light from above-left must produce a highlight on the upper-left of bumps; if inverted, Step 1 (Y-flip) was skipped. Skipping Step 1 before Step 2 produces silently inverted normals on every normal-mapped surface — not detectable by `validate_assets.py`. Step 3 — Compress the Step 2 swizzled PNG to BC3/DXT5 DDS with 4 mip levels: `nvcompress -normal -bc3 -mips 4 input_swizzled.png output_n.dds` (or `compressonatorcli -fd BC3 -miplevels 4 input_swizzled.png output_n.dds`). Compressing the un-swizzled PNG (skipping Step 2's intermediate export) produces silently wrong normals. All three steps must run in order on every normal map asset); (d) specular/roughness → BC1 or BC3 linear pool (`IVideoDriver::getTexture()`); (e) splat maps → **RGBA8 UNORM uncompressed, uploaded via `glTexImage2D(GL_RGBA8)` — NEVER `glCompressedTexImage2D`** (splat maps are not DXT-compressed; artists must verify that the building silhouette remains recognizable at 14×14 px in a DCC tool before approving the billboard atlas asset — an unrecognizable silhouette at mip 3 produces a visual artifact at maximum cull distance; (h) road asphalt tileable (`road_asphalt_tileable.dds`) → DXT5/BC3 raw-GL sRGB path (`GL_COMPRESSED_SRGB_ALPHA_S3TC_DXT5_EXT`) — category b, DXT5 required for alpha channel used in road marking blending; glBindTexture(GL_TEXTURE_2D, roadTexId)`. `SMaterial::setTexture()` CANNOT be used because it requires an `ITexture*` (unavailable for sRGB raw-GL textures);** (i) `road_markings_atlas.dds` → **linear pool (`IVideoDriver::getTexture()`) — NOT the raw-GL sRGB path**; the road markings atlas encodes a decal mask (alpha = blending opacity), not diffuse color data; uploading via the sRGB path causes incorrect gamma brightening of the mask values, altering decal opacity at UV boundaries; anisotropic filtering must be disabled (`GL_TEXTURE_MAX_ANISOTROPY_EXT = 1.0f`) for road markings (decal masks do not benefit from anisotropic filtering)
  - Mip chain rules by category: **terrain base textures** (2048×2048 DXT1/BC1 sRGB only — DXT5 must NOT be used for terrain base textures; terrain diffuse is opaque and requires no alpha channel; using DXT5 wastes VRAM with an unused alpha layer): 4-level mip chain (mandatory cap — `GL_TEXTURE_MAX_LEVEL = 3`; do NOT generate additional mip levels beyond index 3: extra levels waste VRAM without visual benefit at the used LOD range); **normal maps** (DXT5nm): minimum 4 mip levels (mip chain critical — without mipmaps, normal map sampling at distance produces specular aliasing); **specular/roughness** (BC1/BC3): minimum 4 mip levels; **building atlas** (2048×2048): default format is DXT1 sRGB (`GL_COMPRESSED_SRGB_S3TC_DXT1_EXT`), but **must switch to DXT5 sRGB (`GL_COMPRESSED_SRGB_ALPHA_S3TC_DXT5_EXT`) if any atlas cell requires alpha transparency** (e.g., glass windows, facade cutouts — DXT1 supports only 1-bit punch-through alpha, silently discarding smooth alpha); mipmaps cause blur on crisp UI elements); **splat maps** (RGBA8): `GL_TEXTURE_MAX_LEVEL = 0` (no mips); **lightmaps** (`_lm` suffix): `GL_TEXTURE_MAX_LEVEL = 0` (exempt from mip generation — lightmap data is baked to match specific geometry UVs and resolution; generating mips would blend baked lighting values across texels, producing illumination values that match no real baked lighting state; additionally, lightmap atlas VRAM cost is already included in the ≤170 MB scene-VRAM budget at base resolution and mip chain storage would push VRAM over budget); **road textures** (`road_asphalt_tileable.dds`, `road_markings_atlas.dds`): 4-level mip chain (capped at `GL_TEXTURE_MAX_LEVEL = 3`; 1024→512→256→128); road asphalt tileable uses raw-GL sRGB path with minimum 4x anisotropy; road asphalt tileable — minimum 4x; road markings atlas — disabled (1.0f); normal maps (`_n` suffix) — minimum 4x (`GL_TEXTURE_MAX_ANISOTROPY_EXT = 4.0f`); specular/roughness maps (`_s`, `_sp` suffixes) — minimum 4x (`GL_TEXTURE_MAX_ANISOTROPY_EXT = 4.0f`); all other categories — use GPU-default or material setting. ### Architecture Decisions

| Decision | Choice | Rationale |
|---|---|---|
| OGG decoding library | **libvorbisfile** (vcpkg `libvorbisfile`, CMake target `Vorbis::vorbisfile`) | Fully-featured reference implementation of the Vorbis spec; ships with `ov_pcm_seek`, `ov_pcm_total`, and `ov_read` APIs that map directly to the streaming architecture; managed via vcpkg for consistent cross-platform builds with no manual FetchContent wiring. stb_vorbis is excluded: its header-only distribution is incompatible with vcpkg baseline enforcement and its seek precision is insufficient for bar-aligned crossfade calculations. |
| Irrlicht CMake target name | **`Irrlicht`** (bare, no namespace) | Verified via adrido/irrlicht-vcpkg CMakeLists.txt: `install(TARGETS Irrlicht EXPORT Irrlicht ...)` with no `NAMESPACE` argument; `irrlicht-targets.cmake` exports the bare name `Irrlicht`. `vcpkg_fixup_cmake_targets` does NOT add a namespace for this port. Use `target_link_libraries(aitown_render PRIVATE Irrlicht)`. Committed in `CMakeLists.txt`. |
| Windows vcpkg triplet | **`x64-windows` (default dynamic)** — no `VCPKG_DEFAULT_TRIPLET` override | No explicit triplet is set in CI; vcpkg defaults to `x64-windows` on Windows runners, producing DLL builds. Consequence: `Irrlicht.dll` must be copied to the output directory at Phase 1 when `aitown_render` first links Irrlicht. Phase 1 must add a CMake post-build copy rule for `Irrlicht.dll` and add it to the Windows DLL verification step. |
| SimSpeed vs SpeedMultiplier | `SpeedMultiplier` is the canonical enum in `simulation_types.h`; `SimSpeed` is a type alias (`using SimSpeed = SpeedMultiplier`) | Eliminates the name mismatch between `ICitySimulation.h` (uses `SpeedMultiplier`) and `IAudioSystem.h` (uses `SimSpeed`) without duplicating the enum definition. Both names compile; `SpeedMultiplier` is preferred in new code. |
| Markdown linter | `markdownlint-cli` v0.47.0 via npm; `.markdownlint.json` config at repo root | Enforces consistent heading hierarchy, blank lines around structural elements, and language-tagged fences across all spec files. Suppressions: MD013/MD033/MD041/MD060 are inapplicable to dense spec files; MD024 `siblings_only` allows same-name headings in different parent sections; MD029 disabled to permit intentional continuation numbering in shutdown sequences. |
