## Spec Contradictions Flagged

The following contradictions were identified during the spec review. They must be resolved before the affected phase can exit. Items marked **RESOLVED** have been closed based on further spec review.

All open contradictions have been resolved. See the Resolved Contradictions list below.

### Resolved Contradictions

1. **[RESOLVED] Source pool slot [57] V1 treatment** — Confirmed: sources[57] in V1 is **idle** — allocated in the 62-source block by `alGenSources(62, ...)` at pool construction but never returned by `acquireSFXSource()` (range 0..54), `acquireStingerSource()` (indices 55..56), or `acquireStreamSource()` (indices 58..61). The phrase "evictable in V1" in earlier spec drafts was misleading. Post-V1 promotion to `StingerType::GAME_OVER` requires only: add `GAME_OVER=57` to StingerType, increment kStingerCount 2→3, extend the stinger setup loop to include index 57 — no pool restructuring. Spec updated in `source-pool.md`. **Closed in Phase 7 spec pre-work (2026-02-20)**.

2. **[RESOLVED] IAudioSystem method signature and count mismatch** — `architecture/testing/testability-architecture.md` updated to match the canonical 11-method `IAudioSystem` in `architecture/audio-architecture/audio-system.md`. Both files now agree: `playSound(SoundId id, SoundPriority priority, float gain = 1.0f)`, `playPositionalSound(SoundId id, vec3 pos, SoundPriority priority, float gain = 1.0f)`, `setTimeOfDay(TimeOfDay tod)`, and `transitionToGameplay()` are all present. `MockAudioSystem` MOCK_METHOD block updated to 11 methods. **Closed in Phase 0 plan update (2026-02-18)**.

3. **[RESOLVED] Emergency Municipal Bond interest rate** — Both `architecture/game-design/economy-model.md` and `architecture/ui-ux/modal-dialog-system.md` agree at 5%/year. The `economy-model.md` states "5% per in-game year (the same unified rate as forced loans)"; `modal-dialog-system.md` states "5%/year (same rate as forced loans — the bond's distinguishing cost is the doubled principal and 24-tick repayment period)". An earlier draft flag referenced "8%" which was a tax rate example ("Residential: 8% → 8.8%"), not an interest rate. No spec change required; the contradiction flag is closed. All code and tests must use 5%/year per `economy-model.md`. **Closed in Phase 12**.

4. **[RESOLVED] Zone loop channel count** — Zone loops (`zone_residential`, `zone_commercial`, `zone_industrial`) are mono positional (1 channel), pre-loaded into a single AL buffer from the SFX pool, and are NOT streamed. All three relevant audio specs are consistent: `streaming-architecture.md`, `v1-audio-asset-manifest.md`, and `audio-asset-formats.md` all agree on mono. An earlier draft flag referencing stereo was based on a misread of the `streaming-architecture.md` kSamplesPerBuffer section. No spec change required; the contradiction flag is closed. **Inline `SPEC CONTRADICTION` block in `phase-10.md` updated to `[RESOLVED]` on 2026-02-20.** Final QA pass in Phase 12.

5. **[RESOLVED] getDemandPressurePct vs getTrafficDemandFactor** — Both methods remain in `ICitySimulation.h` with distinct semantics, confirmed in `architecture/testing/testability-architecture.md` and `src/interfaces/ICitySimulation.h`: `getDemandPressurePct(ZoneType) const` returns the post-combination HUD aggregate demand [0.0, 1.0] (what the player sees in the demand bars); `getTrafficDemandFactor(ZoneType) const` returns the raw traffic-only smoothstep [0.0, 1.0] for Phase 11 save/load serialization. They are semantically distinct and must both be present. **Closed 2026-02-20.**

6. **[RESOLVED] sfx_budget_warn duration — 1–2 s confirmed** — `architecture/audio-architecture/v1-audio-asset-manifest.md` confirms `sfx_budget_warn` as WAV PCM, 1–2 s, non-looping one-shot, −24 LUFS, −1 dBTP. The 6 s minimum applies to engine loops only; non-looping one-shots have no loop fatigue concern. The `sfx_budget_warn` asset is confirmed as a WAV 1–2 s event chime for deficit threshold crossings. **Resolution: 2026-02-20. Closed.**

7. **[RESOLVED] Phase 1 vs Phase 3 ownership of `WallClock.cpp` and `input_event.h`** — `WallClock.cpp` and `input_event.h` are Phase 1 deliverables per `architecture/testing/testability-architecture.md` (IClock section) and the `CameraController` implementation dependency. `phase-3.md` has been updated to replace the `WallClock.cpp` and `input_event.h` authoring entries with VERIFY entries confirming the Phase 1 deliverables are present. Phase 3 does NOT re-author these files. **Closed 2026-02-21.**

8. **[RESOLVED] phase-2.md "Phase 1 Spike Results" naming vs spec "Phase 2 Spike Results"** — `phase-2.md` previously referenced the GLEW availability spike result section as "Phase 1 Spike Results" in three places (the GLEW spike deliverable, the exit criteria, and the Risks section). The canonical spec (`architecture/graphics-architecture/irrlicht-device-lifecycle.md`, line 209) names the section **"Phase 2 Spike Results"**. This was a plan-spec naming inconsistency (not a spec-vs-spec contradiction). `phase-2.md` updated on 2026-02-21: all references now correctly point to the "Phase 2 Spike Results" section, and a SPEC SECTION NAME NOTE clarification block was added to the GLEW spike deliverable. The spec's "GLEW Spike — Two Independent Questions" detail was also added as a deliverable note to prevent conflation of the two spike questions. **Closed 2026-02-21.**

9. **[RESOLVED] phase-2.md LOD smoke test promoted to "Phase 4" vs spec "Phase 5"** — `phase-2.md` previously stated the LOD smoke test body (`LODSwapSmokeTest.SetMeshGrabDropContract`) is "promoted to Phase 4 when the real LOD swap is implemented". Both `architecture/graphics-architecture/scene-graph-ownership.md` (line 46) and `architecture/testing/framework.md` (line 227) state the promotion occurs in **Phase 5** (when TerrainChunk and the real LOD swap are implemented). The `GTEST_SKIP()` message string and the adjacent comment in `phase-2.md` have been corrected to "promoted to Phase 5". **Closed 2026-02-21.**
