### Retroactive Fixes (applied 2026-02-26, Phase 6 implementation cycle)

Eight implementation-level corrections were required to reach all 116 simulation tests passing. All are now reflected in the relevant spec files:

- **`density_upgrade_wave_demand_threshold` lowered 0.75 → 0.50** (`gamedesign-lookandfeel`): The original threshold of 0.75 prevented upgrade waves from firing at the steady-state null-path demand value (0.5 = `null_path_demand_default`). The wave would never trigger in a city with no road connections, even after the bootstrap period expired. Lowered to 0.50 so waves fire as soon as demand meets or exceeds the null-path neutral value. Spec updated in `architecture/game-design/zoning-system.md` and `simulation_constants.h`.
- **Partial rolling-window average: divide by `min(totalTicks, window_size)`** (`gamedesign-lookandfeel`): During early ticks before the rolling window fills, dividing by the constant `window_size` dilutes valid samples with zero-initialized slots, understating demand. The correct divisor is `min(totalTicks, window_size)`. This is proven by the oscillation sign-off tables in `zoning-system.md` (denominator = number of recorded samples). Spec note added to `architecture/game-design/traffic-system.md`.
- **Budget surplus precomputed at start of `doBudgetTick()`** (`test-dev-cpp`): `doServiceDegradationTick()` read a stale `budget_surplus_pct = 0.0f` because the surplus was not yet computed when degradation checks ran. Moved surplus computation to the top of `doBudgetTick()` so all sub-ticks read the correct value. Implementation detail only — no spec change.
- **`anyUncovered = true` when no service buildings placed** (`gamedesign-lookandfeel`): When zero service buildings exist, every residential tile is uncovered; `anyUncovered` must be set to `true` immediately (not left `false` by the building-iteration loop that finds nothing). Grace-tick logic still suppresses the −5 desirability/tick penalty on the first tick. Spec note added to `architecture/game-design/service-coverage.md`.
- **`computePowerCoverage()` radial fallback for disconnected grid** (`graphics-dev-irrlicht`): When BFS from a Power plant cannot reach a candidate tile through placed tiles (disconnected grid), power coverage falls back to a radial-distance check. Without this fallback, isolated tiles were silently uncovered regardless of proximity to the plant. Spec note added to `architecture/game-design/service-coverage.md`.
- **`wasAlreadyUnlocked[]` snapshot prevents upgrade wave on same tick as first unlock** (`gamedesign-lookandfeel`): Without the snapshot, a tier that unlocked on the current tick immediately drove an upgrade wave in the same `doDensityUnlockTick()` call, firing the wave before the player received any notification. A `bool wasAlreadyUnlocked[6]` array is taken at the top of the function; only tiers already unlocked before this tick participate in the wave. Spec note added to `architecture/game-design/zoning-system.md`.
- **PowerPlant degradation is silent (no `SFX_SERVICE_DEGRADE`, no RNG roll)** (`sound-dev-opensoftal`): The Power plant's brownout model is fully deterministic — it enters the degraded state without an `ISimulationRNG` roll and without triggering `SFX_SERVICE_DEGRADE`. Only Fire, Police, and Water stations use the stochastic degradation path with audio. Spec clarified in `architecture/game-design/service-coverage.md`.
- **`SFX_BUDGET_WARN` gated on `m_firstRevenueTicked`** (`gamedesign-lookandfeel`): The budget deficit warning at −25% surplus fires `SFX_BUDGET_WARN` and enqueues `BudgetDeficitWarn` only after the first non-zero revenue budget tick — the same gate as the forced loan mechanic. This suppresses spurious warnings during the early-game period when service upkeep creates a deficit before any tax income is generated. Spec note added to `architecture/game-design/economy-model.md`.
